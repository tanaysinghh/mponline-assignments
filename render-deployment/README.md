# Adult Census Income — Render Deployment

A Flask web service that predicts whether a person earns more than \$50,000 per year
from demographic and employment features, served as both an HTML form and a JSON REST API.

The model is a Logistic Regression trained on the UCI Adult Census Income dataset
(32,561 records, 14 features). Measured test accuracy: **85.21%**.

```
              precision    recall  f1-score   support

       <=50K       0.88      0.93      0.91      4945
        >50K       0.74      0.60      0.66      1568

    accuracy                           0.85      6513
```

## Project structure

```
render-deployment/
├── train.py             Trains the model, writes model.pkl / scaler.pkl / feature_columns.pkl
├── app.py               Flask app: "/" form UI, "/predict" JSON API, "/health" health check
├── requirements.txt     Flask, gunicorn, scikit-learn, pandas, numpy, joblib
├── Procfile             web: gunicorn app:app
├── templates/
│   └── index.html       Form for all 14 input features plus result display
├── static/
│   └── style.css        Styling
├── .gitignore
└── README.md
```

Model artifacts and the dataset are **not** committed — they are regenerated by
`train.py` during the Render build.

## Model details

| Step | Detail |
| --- | --- |
| Dataset | [Adult Census Income](https://raw.githubusercontent.com/pooja2512/Adult-Census-Income/master/adult.csv) — downloaded and cached as `adult.csv` on first run |
| Missing values | `?` replaced with `NaN`, then filled with the column mode |
| Categorical encoding | `pd.get_dummies(..., drop_first=True)` → 97 input features |
| Numerical scaling | `StandardScaler` on `age`, `fnlwgt`, `education.num`, `capital.gain`, `capital.loss`, `hours.per.week` |
| Split | Stratified 80/20, `random_state=42` |
| Model | `LogisticRegression(max_iter=1000, random_state=42)` |

`feature_columns.pkl` stores the exact ordered column list produced by one-hot encoding.
At inference the app one-hot encodes the single input row, reindexes it against that stored
list (filling absent dummies with 0), and applies the stored scaler — so the feature vector
is identical to what the model saw during training.

## Local setup

```bash
cd render-deployment

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
python train.py                  # downloads the dataset, trains, writes the three .pkl files
python app.py                    # http://localhost:5000
```

`train.py` takes well under a minute. It must be run before `app.py` — the app raises a
clear error at startup if the artifacts are missing.

To serve locally the same way Render does (Linux/macOS only, gunicorn does not run on Windows):

```bash
gunicorn app:app
```

## API usage

### `POST /predict`

```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 45,
    "workclass": "Private",
    "fnlwgt": 160323,
    "education": "Masters",
    "education.num": 14,
    "marital.status": "Married-civ-spouse",
    "occupation": "Exec-managerial",
    "relationship": "Husband",
    "race": "White",
    "sex": "Male",
    "capital.gain": 0,
    "capital.loss": 0,
    "hours.per.week": 50,
    "native.country": "United-States"
  }'
```

```json
{"confidence": 0.8152, "prediction": ">50K", "probability": 0.8152}
```

- `prediction` — `"<=50K"` or `">50K"`
- `probability` — probability of earning **>\$50K**
- `confidence` — probability assigned to the predicted class

All 14 fields are required. Underscore key names (`education_num`, `marital_status`, …)
are accepted as aliases for the dotted names.

Invalid input returns HTTP 400 with an explanatory message rather than a 500:

```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"age": "thirty"}'
```

```json
{"error": "'age' must be a number, got 'thirty'"}
```

### `GET /health`

```bash
curl http://localhost:5000/health
```

```json
{"status": "ok"}
```

## Deploying to Render

1. **Push this repository to GitHub.**

2. In the [Render dashboard](https://dashboard.render.com), click **New → Web Service**.

3. **Connect the repository.** If this project lives in a subdirectory of a larger repo,
   set **Root Directory** to `render-deployment`.

4. Configure the service:

   | Setting | Value |
   | --- | --- |
   | Runtime | Python 3 |
   | Build command | `pip install -r requirements.txt && python train.py` |
   | Start command | `gunicorn app:app` |
   | Health check path | `/health` |

   Training during the build is deliberate: the `.pkl` files are gitignored, so the build
   step regenerates them into the same filesystem the web process runs from.

5. **Environment variables:**

   | Key | Value | Why |
   | --- | --- | --- |
   | `PYTHON_VERSION` | `3.11.9` | Pins the interpreter so the pinned wheels resolve |

   No other environment variables are needed. Render supplies `PORT` automatically and
   gunicorn binds to it without extra configuration.

6. Click **Create Web Service**. The first build takes a few minutes (installing
   scikit-learn/pandas plus training). When it finishes, the service is live at
   `https://<your-service-name>.onrender.com`.

### Notes on the free tier

- Free instances spin down after inactivity; the first request after idling can take
  ~30–60 seconds while the service wakes.
- The filesystem is ephemeral. Because the model is retrained on every build rather than
  stored, this costs nothing — but any files written at runtime will not persist.

## Notes

- Predictions come from 1994 US census data and reflect the biases present in it. This is a
  coursework demonstration and should not be used to make decisions about real individuals.
- `education` and `education.num` encode the same information two ways, and both are kept
  because both are in the original feature list. Keep them consistent
  (e.g. `Bachelors` ↔ `13`) for sensible predictions.
